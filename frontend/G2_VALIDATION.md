## 五页结果

| 页面 | 本次实现 | 保留的边界 |
|---|---|---|
| 需求探索 | 对话与可收起的六维 Inspector；独立审阅；已确认时优先确认信息和下一阶段 | 当前版本审阅、纠正后重新勾选、显式确认与重新探索；恢复不自动提问 |
| 理解仓库 | 局部导航与阅读区；保存分析优先，登记授权另行展开 | 原始 Evidence、完整 analyzedRevision、快照和资产 ID；授权与分析分别提交 |
| 产品方向 | 紧凑列表与单个详情，完整内容可展开，历史方向单独查看 | 查看不触发 Select；Select / Reject 仍需明确操作；失效依据不能选择 |
| 演化规划 | 紧凑 Current / Target，完整原文可查；有序路线每次内联展开一个 Step | 历史轮次与 baseline；Plan 准备和每个 Step 的授权分别确认 |
| 验证演化 | Step Navigator、目标与授权、执行与 Candidate、验证与可信版本；副本元数据折叠 | 原有执行守卫与风险确认；Candidate 不等于验证通过；无自动执行或恢复入口 |

新增只读组件 `DirectionListEntry` 与 `StepPrerequisites`。共享样式统一折叠、阅读、局部导航、
普通上下文和阻塞提示；窄屏查看方向或步骤后将焦点移到详情，提供返回列表入口。

## 数据限制与验收结论

Step DTO 没有独立的规划前提字段，页面仅展示现有顺序、Plan / WorkingCopy 状态与
revision 要求。API 没有历史聊天、已接受 CodingProposal 或源码 diff 查询，页面不补造。
失败与恢复状态保留实际结果和提示，M5 恢复操作仍未提供。

原始 G2 的本地功能实现和合成验证 PASS；用户视觉验收未通过，不能将功能 PASS 视为视觉接受。
本记录不代表真实 Provider 或端到端执行验收，最终付费 E2E 仍按原约定留待 UI 验收后进行。
