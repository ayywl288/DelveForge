# 项目对话工作台

## 项目文件

空项目和不含 Git 仓库的普通目录都在副本中建立独立的 Git 根目录，初始分支为 `main`。

在「新建或导入项目」中选择「从本机导入」，点「选择文件夹」打开 Windows 目录选择器。选择后会填入文件夹路径和默认项目名称，可以改名。点击「创建工作副本」才开始导入。也可以选择手动输入路径。

「新建或导入项目」先在 Windows 暂存目录构造独立副本。Git 项目固定当前提交和分支，分离 HEAD 与尚无提交的分支也保留。副本以该提交建立索引，再复制源目录当前文件，包括已修改、删除、未跟踪文件及被忽略的项目配置。部分暂存的修改在新副本里体现为工作树修改。Git 对象独立复制，导入时移除指向源目录的临时 origin。

导入会跳过可重新生成且没有已跟踪内容的 `node_modules`、`target`、`dist`、`.vite`、`.pnpm-store`、`__pycache__`、`.venv`、`.gradle`。外部联接、符号链接、嵌套 Git 仓库或子模块会产生具体错误。源 HEAD 或相关内容在复制中发生变化时，导入失败，稳定后可重试。文件写入 Windows 副本后立刻可被 Linux 和编辑器读取。「打开文件夹」从工作台打开这个位置。

Linux 依赖安装在各项目的正常解析目录，共用下载缓存。若改用 Windows 原生工具执行项目，应按该平台重新安装包含本机二进制的依赖。再切回 Linux 也按 Linux 平台重装。需要热更新的项目可在自己的 Vite 配置中启用 `server.watch.usePolling`。是否需要轮询取决于当前挂载实际发送的文件事件。

## 对话、运行和费用

同一项目可以有多段对话，历史和输入分别保存。整个开发环境同一时间有一个前台 Run。有 Run 正在运行时，新消息先保存。当前对话的纠正会在未开始的工具或最终答复提交之前生效。其他对话的消息保存在各自对话中，环境空闲时可以点「继续此对话」。刷新页面只读取现状。

每个新任务默认最多发送 96 次模型请求。发送第一条消息时可设置任务总上限（1 到 10000 次）。额度包括工具决策、摘要和网络重试。达到上限后，输入更高的**总上限**即可继续同一 Run。因其他原因暂停时，继续会沿用原额度与已记录的执行结果。排队的任务保留首条消息选择的上限。

页首显示当前项目、对话和任务状态。侧栏的「模型与用量」可查看累计请求、提供方已报告的 tokens、适配器、服务端点来源、请求模型 ID、思考模式、单次上下文和输出预留。准确费用以提供方账单为准。部署端的具体权重无法从请求模型 ID 独立确认。

侧栏按项目收纳对话，窄屏可从左上角展开。草稿按对话保存在当前浏览器标签页，刷新或切换项目后可继续输入。用 Ctrl+Enter 或 ⌘+Enter 发送。收到服务端确认后显示「消息已保存」。如果发送中断，保留原文重试会沿用原请求标识。浏览其他对话时可用「回到该对话」找到占用开发环境的任务。

「工作副本」显示 Windows 路径，可以复制或打开文件夹。文件写入清单依据本对话成功的 Write 和 Edit 回执，展开可查看写入内容或当时替换的前后文本。Bash 和外部编辑器的修改可直接在工作副本中检查。对话里登记的本机预览也会出现在此面板。

助手消息支持 Markdown 和代码复制。连续工具调用收在一行摘要中。一次任务有多段操作时，还可展开「工作过程」逐段查看。收起时可见失败次数和输出缺口，展开单次调用可看原始参数、退出码和分页输出。工具摘要和工作副本的文件清单按项目根目录显示路径，例如 `.gitignore` 或 `src/main/App.java`。

对话等待下一条助手回复时会显示三个跳动的小点。工具开始处理、收到最终回复或任务暂停后，提示消失。开启系统的减弱动画后，小点静止显示。浏览旧消息时可以点「回到最新」恢复自动跟随。

压缩对话时，已进入摘要范围的本任务用户原文，以及此前任务中最近三条已被摘要覆盖的用户消息，按原顺序、以用户身份传给模型。尾部消息只发送一次。摘要失败时仍保留这些原文，原文只计算一次。必要内容超出单次上下文容量时，任务会暂停。

## 工具与历史

| 工具 | 输入与可观察结果 |
| --- | --- |
| Read | UTF-8 文本用 `path`、起始行 `start` 和行数 `count` 分页。返回整文件 SHA-256 版本、实际文本和下一行或 EOF。单页最多 500 行、16,000 字节。超过单页的单行和二进制文件可用 Bash。多页读取期间外部编辑可能改变版本。 |
| Edit | `old` 原文必须唯一，`new` 是精确替换文本。无匹配、多个匹配或内容版本已变时返回冲突。 |
| Write | 新文件排他创建。完整替换已有文件须带 `expectedVersion`，来自 Read 返回的整文件版本。文本修改上限为 1 MiB。保存前再次核对并在同目录原子替换，外部编辑器和 Bash 不参与该检查，仍可能在最后核对与更名之间竞争。 |
| Bash | 每次从该项目的 Linux 根目录打开新的 Bash。上一条命令的 `cd` 和 `export` 随 shell 结束。文件、已安装软件、项目数据以及主动脱离前台并重定向标准流的服务可继续使用。 |

已准入的工具可以通过 Bash 使用以下限定到当前对话的命令。目录查询按记录序号分页。单条记录与输出按字节分页，返回 Base64 原文、下一偏移或 EOF。输出保留 stdout、stderr 的采集顺序。

```bash
df-workbench history --offset 0 --limit 12
df-workbench history 42 --offset 0 --limit 4096
df-workbench output <invocation-id> --offset 0 --limit 4096
```

「部分已捕获输出」可以继续翻页。「部分输出未捕获」表示有一段时间采集不完整。系统无法确定这段时间产生了多少字节，也无法补读。退出码可以未知。语义压缩只改变模型收到的视图，会保留完整工具配对、覆盖位置和后续新输入。原始记录仍可查询。

## 本机预览

请 Agent 启动项目自己的 HTTP 服务，选择合适端口，确认服务在 Linux 环境内的回环或通配地址监听，再在该项目的工具调用中执行以下命令。

```bash
df-workbench preview 5173
```

例如，静态网页可用 `setsid -f python3 -m http.server 5173 --bind 127.0.0.1 </dev/null >preview.log 2>&1` 留在独立后台，确认页面可访问后再登记。

工具返回当前 Windows 浏览器可访问的 `http://p-….localhost:<动态端口>`。在对话里选择「打开本机预览」。需要跨服务访问时，由项目自己的开发服务器将例如 `/api` 转发给实际后端。登记支持 HTTP 和 WebSocket。认证挑战和重定向属于有效 HTTP 响应。监听服务退出、更换或网关重建后，请重新登记。预览按需使用。

## 恢复

停止 Run 时只核对并结束受管前台执行，已经产生的文件修改保留。控制端中断后会封住迟到的启动，检查原容器、Docker exec 和原前台进程组。确认原执行已结束即可释放占用。查不到历史退出码或失联期间的输出会写进工具记录。若经过有限次核对仍无法证明原执行已结束，Run 显示「需要核对」，可以在 Docker 恢复后选择「重新核对执行」。只有显式重启共享环境才会影响所有项目的后台进程。

之后继续对话时，Agent 可检查当前文件和服务，再决定下一步。系统不会自动重放可能已产生效果的命令。多个项目共用单用户开发环境，项目目录和调用授权提供逻辑归属。需要相互不信任的多人隔离不在这个部署范围内。
