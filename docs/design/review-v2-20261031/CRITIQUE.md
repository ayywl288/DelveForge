# 独立审查与修正

2026-10-31 · 两位隔离评估者 · 首轮审查后一次集中修正与有界复查

本文首轮表格是审查历史，不是终稿所有排布的要求。产品负责人后续明确要求恢复交互对话与时间线，
并将代码结果留在底部；最终已按这一偏好调整。独立审查建议不能覆盖产品负责人的明确决定。

Assessment A 未接触 detector 输出。它查看九个桌面场景与选定 320/420/768 场景、V1 比较及实际浏览器，认为 V2 已改变结构，但运行层级未完成；首轮 Nielsen 分数 26/40。此分数不代表最终版本接受。

Assessment B 对首轮生产构建 `index-BS5hniXF.css` / `index-DIaNJo6N.js` 检查 45 个场景/尺寸与 AX 控件名、对比度、焦点、长文本，并运行实际 Impeccable source detector，返回 `[]`。首轮有界审计 14/20（可访问性 3、性能 3、主题 3、响应 2、实现一致性 3）。两个评估的结论独立完成后才合并。

| 发现 | 实质修正 | 复查 |
|---|---|---|
| 规划标题被挤成竖排 | 取消旧步骤号 absolute 定位；标题占弹性列，状态另起一行；概览与副本准备并排 | A 确认 1440/420 可正常阅读，桌面路线首屏可见 |
| 手机运行中先读配置才能停止 | DOM 顺序改为运行面先、配置后；增加当前活动入口 | A 确认 420 停止操作在配置之前 |
| 终态先看统计而后看结果 | 抽取只负责展示的 AgentResultSurface；有 Candidate 时放在活动前 | A 确认 Candidate 320 的重交付与测试、Delivery 1440 的接受文件与未测试事实均在历史前 |
| 空白运行历史轨道 | 原侧栏改为原生 disclosure，移除冲突 grid；时间归入技术详情 | A 确认空轨道消失 |
| 手机丢失项目身份 | 页面头部保留真实当前项目名 | A 确认可见 |
| 手机候选没有问题预览 | 保留候选的问题描述 | A 确认 320 仍可比较 |
| 对话按钮呈现不统一 | 改为规则线下的视图切换 | 实看与最终截图 |
| 侧栏英文对比度 4.21:1，调试项 1.57:1 | 深化真实文字色；侧栏小字至少 11px | 最终测量复核，不把 sr-only 或装饰数字当正文 |
| 某些手机控件小于 44px | 对菜单、刷新、对话切换和跳转补明确最小高度 | 按真实控件测量；不把所有小目标一律宣称为 WCAG 失败 |
| 断点后浏览器把焦点先退回 body | 记录导航内焦点，断点后交给可见菜单或品牌；同阶段选择也关闭菜单 | 自动回归 + 实际浏览器检查 |

A 的最后有界复查确认上述结构修正，未重新打分。它保留「交付阻塞原因过于笼统」意见；随后结果面增加后端实际 `delivery.reason` 的原文展示，不推测或翻译未定义的业务含义。

## 产品负责人反馈修订

- 对话恢复左右角色气泡，保留 revision 笔记；实际请求等待显示文字和三点动效，减少动态效果时静态提示仍在。
- 路线恢复连续节点时间线，内容在所选节点内展开；状态、顺序、前提与逐步授权均不变。
- 所有执行状态先显示实际事件，再显示统计；代码变更与正式交付统一在底部，通过摘要链接快速到达。
- 补充等待中的生产界面夹具捕获，防止只检查静态聊天截图而遗漏交互反馈。

更新后的独立有界审查确认三项改动符合产品负责人偏好；发现正常等待同时出现「上一轮结果待核对」
恢复条。已将恢复条限制在当前请求不处于实际等待时显示，保留请求不确定后的原有查询/放弃行为，
并在发送等待回归中验证不会出现该误导提示。除此之外，三项改动未发现阻断性视觉问题。

局限：独立审查是合成夹具下的界面评估，不是实际后端/Provider 的业务验收。未做 NVDA、物理触屏、真实付费运行或全流程性能分析。Questions skipped: 用户已明确授权自主设计与独立审查，无未决产品行为冲突。
