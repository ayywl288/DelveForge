# ADR-0016：源码凭据的变更感知保护

Status: Accepted for current implementation; genuine acceptance remains separately evidenced.
Date: 2026-10-26

## 问题与授权

用户明确要求调查 SOURCE_CREDENTIALS 的真假风险，允许安全演化普通 JWT 源码，而非把旧拒绝当作终止任务的理由。
FinTrack api.js 的本地只输出形态核验确认三处保守赋值命中：两处函数表达式、一处运行时调用；未命中其他已知私钥/令牌规则。
未输出、记录或向模型发送命中取值。普通认证辅助函数被保守出站策略误当作整个文件的编辑禁令。

ADR-0012 的整文件拒绝是先前有意选择；它没有提供局部编辑所需的跨度、前置校验与冻结证明。
本决策显式替代该整文件禁令，符合本次用户授权，不把文档沉默当作旧保证。M1–M3 的 ADR-0006 保守出站净化不变。
模块方向、Workspace 权限、敏感路径、沙箱隔离、确认/可信基线和 Candidate/Delivery 状态合同不变。

## 决策

1. RepositorySecretPolicy 增加纯函数的源码视图和写入保护行判定。普通源码的运行时标识符/调用、
   storage/environment/header 等取值和函数表达式可识别为代码；不按熵、测试目录或示例名字猜测字面量真假。
   字面量、已知令牌/私钥/连接串/头部值继续保护；配置文件不获得源码表达式例外。未知实现默认保守拒绝。
2. 保护单位是完整凭据物理行，包括多行私钥的每一行；这些行不可删除、替换、增加或改变模式。
   同文件其他行可以编辑。保留字节不代表证明了程序数据流安全，也不承诺可以修改凭据所在同一行的其他代码。
3. Agent 源码读取和搜索必须先在完整有界文件上识别、逐行净化，再切片/提取命中，保留 LF/CRLF 和行号。
   私有原文材料字段只在基础设施内使用，不进入模型结果、持久化事件或日志。Application 仍逐字段强化出站保护。
4. 每次补丁先在私有临时副本中以真实 Git 预演，得到全部目标的前后像、模式和零上下文变更范围。
   全部路径/内容/规则检查通过后才调用实际应用；实际边界核对所有前像，Git check 后再核对，应用后核对全部后像。
   前像冲突确认未写入；实际应用及后像不确定仍终止，不能作为可恢复的未写入结果。
5. edit_file 只生成实际变动行的标准 diff，不把相邻原文凭据复制到补丁。没有模糊匹配或秘密回填。
   新增修改行不得包含脱敏占位符；秘密行也不能被占位符覆盖。源码外敏感路径仍在访问前整份禁止。
6. 最终冻结独立从基线 R 与实际停止后的源码树重算变更，不信任工具阶段的判断。
   构建或其他程序引入/改动凭据也不能绕过冻结。最终 D 使用零上下文并去掉 Git 函数标题，
   避免未变秘密被相邻上下文或标题写入数据库/UI。独立 index 重放、tree B、正式 C 的 parent=R 不变。
   Delivery 的受控 Git 重放支持 --unidiff-zero，仍核对完整基线、预期树、原生文件写入和 SQLite 原子接受。
7. 工具协议升级为 v3，宿主拒绝不具备预演/前后像能力的旧镜像。启动器按实际输入重新构建并验证固定镜像，
   不重置 Docker、不清理历史缓存。资源、超时、模型预算和既有一次写入前修正上限不增加。

## 替代方案与边界

只修改提示无法改变安全写入判定；关闭扫描或测试/FinTrack 特例会失去保护；整文件允许并只检查新文本会
漏掉删除/替换及构建侧写入；在脱敏文本上回填秘密会使授权和重放难以证明。因此选择同一政策下的独立变更判断。
没有引入通用语言解析器或新依赖。运行时表达式识别范围是当前选择，无法确定的字面量位置继续保护。
已知规则仍不等于检测所有可能秘密；未知格式、编码/分片等既有检测限制没有被宣传为已解决。

该变更的代价是私有 Git 预演和最终复核，以及对有秘密行的编辑粒度限制。没有扩大模型的文件/执行权限。
实际字面量、重写/删除/占位符、敏感路径、跨文件预像冲突、后像不确定、分片读取和冻结绕过必须有确定性回归，
随后以合成 Docker 夹具验证实际镜像，再开始有实质修复依据且用量有界的真实 Provider 验收。
