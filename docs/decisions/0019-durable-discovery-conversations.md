# ADR-0019：持久需求对话与版本充分性

- 状态：Accepted
- 日期：2026-10-29

## 背景

页面内存无法在刷新或重启后恢复问答；客户端问题列表也不能可靠避免重复。
画像保存成功但响应丢失时，仅读取画像无法判断某轮是否已接受。
用户授权本轮在既有 User Discovery 内解决连续性，保持事实、Evidence 和显式确认边界。

## 决策

- Application 拥有独立对话持久化 Port；Infrastructure 使用现有 SQLite / Spring 事务及 V27 增量迁移。
- 消息按画像保存，另存发起项目身份、顺序、时间和精确问题；会话不是 Profile 内容或 Evidence。
  共享同一画像的项目共享需求历史，提供项目身份时校验真实关联。
- 先登记请求身份，模型在事务外运行；画像、版本判断、消息和完成结果最后同事务提交。
  同请求复用结果，单画像最多一个未决请求；并发版本/状态/项目关联变化拒绝旧结果。
- 未决请求只读查询；NOT_FOUND 不证明安全重发。显式取消留下提交屏障，不能撤销完成结果，
  不保证停止在途模型计算。仅进程确认退出或 PID 复用才将其遗留请求标为中断。
- 续聊只发送有界近期消息及紧凑话题/跳过状态，本地检查历史问题的近似文本重复。
  语义判断仍依赖模型；拒答和指代不是用户事实，真实输入主动重开才解除跳过。
- 当前画像版本缓存正负充分性及缺口；无新事实不改判，内容变化后失效。
  确定性最低要求和显式审阅/确认仍独立执行，同版并发不同判断拒绝覆盖。
- 浏览器只持久保存身份，加载不调用模型；旧画像无记录显示空历史。

## 取舍

不引入外部消息服务、向量库或完整对话回放提示。SQLite 请求元数据与消息有存储成本，
但提供可核对的恢复边界；保留客户端内存方案无法满足刷新与响应丢失恢复。
短文本相似检查无法穷举语义改写，测试替身也不能证明真实模型质量。
独立存储对话不改变 User Profile Aggregate、Evidence 字段或 Coding Agent 的运行恢复策略。
