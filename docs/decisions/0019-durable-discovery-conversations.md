# ADR-0019：持久需求对话与版本充分性

- 状态：Accepted
- 日期：2026-10-29

## 背景

页面内存无法在刷新或重启后恢复问答；客户端问题列表也不能可靠避免重复。
画像保存成功但响应丢失时，仅读取画像无法判断某轮是否已接受。
用户授权本轮在既有 User Discovery 内解决连续性，保持事实、Evidence 和显式确认边界。

## 决策

- Application 拥有独立对话持久化 Port；Infrastructure 使用现有 SQLite / Spring 事务及 V27 增量迁移。
- 消息按画像保存，另存发起项目身份、顺序、时间和精确问题；会话不是 Profile 内容或 Evidence。
  共享同一画像的项目共享需求历史，提供项目身份时校验真实关联。
- 先登记请求身份，模型在事务外运行；画像、版本判断、消息和完成结果最后同事务提交。
  同请求复用结果，单画像最多一个未决请求；并发版本/状态/项目关联变化拒绝旧结果。
- 未决请求只读查询；NOT_FOUND 不证明安全重发。显式取消留下提交屏障，不能撤销完成结果，
  不保证停止在途模型计算。仅进程确认退出或 PID 复用才将其遗留请求标为中断。
- 2026-10-29 初版续聊只发送有界近期消息及紧凑话题/跳过状态，本地检查历史问题的近似文本重复。
  语义判断仍依赖模型；拒答和指代不是用户事实，真实输入主动重开才解除跳过。
- 当前画像版本缓存正负充分性及缺口；无新事实不改判，内容变化后失效。
  确定性最低要求和显式审阅/确认仍独立执行，同版并发不同判断拒绝覆盖。
- 浏览器只持久保存身份，加载不调用模型；旧画像无记录显示空历史。

## 取舍

初版只向模型发送近期消息，本次修订改由实际预算决定发送范围。SQLite 请求元数据与消息有存储成本，
但提供可核对的恢复边界；保留客户端内存方案无法满足刷新与响应丢失恢复。
短文本相似检查无法穷举语义改写，测试替身也不能证明真实模型质量。
独立存储对话不改变 User Profile Aggregate、Evidence 字段或 Coding Agent 的运行恢复策略。

## 2026-11-09 修订：引导式对话

两个阶段复用同一份按请求身份分组的已接受历史。指令与历史构成稳定前缀，末尾放当轮结构化材料。
每次请求按实际输出预留量计数，token 或序列化字节触及预算时只从模型输入移除最早完整轮次。
这取代了初版的八条消息窗口。模型仍只提出建议，应用校验上一问结果、下一步动作与当前充分性。
只有规划输出不合法时允许一次定向修正。旧问题可被替换，明确跳过的维度才进入持久跳过记录。

V29 保留原消息序号与请求身份，约束每份画像至多一个待答问题。首次可审阅时的内联选择
与该轮结果原子保存。后续接受输入或主动索取问题记为继续，进入审阅记为审阅。
已确认画像显式重开时才重新取得邀请资格。请求和历史读取不会触发模型调用。


## 2026-11-10 修订：画像整轮批准与人工保护

以 Application 的完整分区分类替代字符串摘录和模型 replacement 授权。未保护区只允许原样有序前缀上的
无重复追加自动写入；其他内容变化整轮待批。V30 以小型保护表和单个提案快照保存人工边界与四态结果，
沿用短事务、请求指纹和乐观版本检查，不引入新的 Aggregate 或通用批准框架。

人工 PATCH、最终确认和接受提案建立保护，重开不清除；旧库没有可靠修改人记录，迁移时保护全部六区
（包括空区），代价是旧画像的普通新增也可能需要一次批准。新建画像不预设保护。
批准读取服务器快照，在一次事务中写画像、依据、保护与结果版本；忽略保留原内容和依据。
重复批准返回原结果，过期版本或状态不能覆盖当前画像。人工编辑与状态变化使待批提案失效。
待批与聊天轮原子保存，页面恢复只读服务器状态。规划只看到接受后的事实和待批标记，使用 PAUSE、
不邀请首次审阅，不制造新 ASKED；上一问仍按真实输入处理，批准/忽略不触发模型。

该设计接受偶尔整轮需要用户一次确认的成本，不尝试证明自然语言语义相等。新增的正文与追问
语义重合拒绝已移除；保留历史提问检查、提示指导和数据库唯一待答约束。

## 2026-11-11 修订：对话归一化与可辨认恢复

保留原两阶段和所有原子性、版本、批准边界。模型理解语义并提供正文，Application 协调可恢复的
nextAction / previousQuestionState / nextQuestion / questionArea / 充分性冲突，不为这些字段额外调用模型。
缺失处置保留真实未答问题，重复可选问题丢弃；待批固定 PAUSE；邀请和同版充分性由服务器控制。
完整但不可用的模型输出直接明确失败，没有隐藏修正重试；断线仍只查询原操作。
未知时间不作为硬审阅缺口，不解释成拒绝、无约束或具体时间；既有确定性目标、能力和用户依据检查保留。

QUESTION 可带默认 false 的 replacePendingQuestion，纳入请求指纹。显式换题原子替换旧问题，
不拒答整个维度、不产生个人事实，失败仍保留旧问题，无需新迁移或状态机。
批准后继续是两个可分辨的动作：先提交批准，再恢复待答问题或以独立身份索取问题；
保留不调用模型的“仅接受更新”。后续生成失败不撤销批准，批准丢响应可 GET 精确提案终态。

原文不进长期 localStorage；仅用 sessionStorage 有界保存未发送/确认失败/未决的本地原文，
最多五份画像、每份四条尝试与一份12000字符草稿；尝试超过一天清除、草稿闲置一天过期。它们不进入服务器历史或模型语境。
确认失败可以编辑并以新身份发送，未决必须保留原身份查询，直到终态或显式取消屏障建立。
代价是关闭标签页、超期、超过数量或浏览器禁用存储后草稿可能不可恢复；已接受历史仍由服务器恢复。

## 2026-11-11 补充：普通对话直接生成正文

获准更新和真实复测后，首次十次 Provider 调用中的第十次返回 HTTP 200、stop 与 DONE，
content 长度为零，completion_tokens 与 reasoning_tokens 同为462。整轮正确失败且没有半轮写入；
完整 JSON 示例仍未避免本次只有思考、没有正文的返回。这是新实测证据，不追认截图那次失败的具体原因。

当前选择让 TURN / QUESTION 的规划与事实提取均显式关闭思考，直接输出既有 JSON 契约。
保留现有模型、端点、两阶段流程、完整终止与结构校验；不解析或展示 reasoning_content，不增加重试。
该参数选择减少普通对话对思考后正文生成的依赖，不承诺提供者永不返回空白。

Application 的 AiRequest 显式携带既有 EXTRACTION / DIALOGUE 预算身份，Infrastructure 按该身份
使用各自配置的输出上限。两阶段仍为8192 / 16384，不因二者都关闭思考而错误共用提取预算；
历史截断仍按实际请求模式及该阶段预留量计算。其他用例和 Coding Agent 的思考配置不受影响。
