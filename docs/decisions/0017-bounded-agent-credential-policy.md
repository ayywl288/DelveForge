# ADR-0017：有界的 MVP Agent 凭据政策

Status: Accepted under the user's 2026-10-26 simplification authorization.
Date: 2026-10-26

## 问题与既有约束

ADR-0016 为普通 JWT 源码增加表达式白名单，随后又因注释/字符串上下文提出词法分析。
Run06 在 13 次模型回复、170342 报告 tokens 后为这项审查取消，没有 Candidate 或 Delivery。
实现正在承担通用源码秘密分析职责，偏离单人本地 MVP；继续枚举表达式不能证明任意源码安全。

用户已明确授权缩减这类保证。隔离、资产授权、逐 Step 确认、可信 revision、未知写入失败关闭、
Git/SQLite 来源及正式 Delivery 仍是必须保留的边界，不能用简化凭据识别削弱它们。

## 决策

- 删除 `SourceCredentialExpression`，不增加词法器、AST、数据流分析或语言例外列表。
- M1–M3 的保守出站净化及凭据路径排除保持。Agent 同样不能读取或修改明确凭据文件。
- Agent 对 Java/JS/TS/JSX/TSX/Vue/Kotlin 源码使用已知密钥/私钥/JWT/连接串/Authorization
  格式规则，以及凭据键直接赋值的单引号、双引号或无插值反引号字面量规则。
  空字面量与单独的 `Bearer ` / `Basic ` 方案前缀不视为凭据；配置和其他文本仍使用保守规则。
- 普通未加引号的运行时表达式保持可见和可编辑，不推断表达式是否合法或是否含派生秘密。
- 已命中的物理行继续脱敏且不可改动；其他行允许编辑。保留写入前私有 Git 预演、前后像核对、
  停止后独立冻结检查和零上下文 D。这些机制维护实际写入与冻结材料的一致性，已有测试覆盖。

## 明确缩减的保证

Agent 不再识别源码中无已知格式的未加引号值、间接赋值、函数参数、字符串内嵌配置、
插值/拼接片段中的任意秘密。未知格式、编码和数据流本就不受完整保证。
识别规则可能误报直接字面量，也可能漏报秘密；不是“源码无秘密”的证明，不能用于恶意仓库托管。
本决定替代 ADR-0016 的表达式分类合同，保留其受控写入与冻结合同；不改变领域状态机或模块依赖。

## 替代方案与取舍

保留整文件拒绝会继续阻塞普通认证实现；继续补表达式/词法白名单会扩大维护成本；
完全关闭出站保护会暴露明确凭据。选择可直接测试和陈述的规则集，在已授权的本地仓库中完成 MVP。
代价是上述检测范围主动缩减。没有新依赖、迁移、资源或模型输出上限变化。

确定性测试须同时覆盖普通 token 处理、明确字面量/已知格式、注释字符串中的已知格式、
配置保守性和已缩减的边界；真实 FinTrack 验收单独记录，测试通过不等于业务交付。


## 2026-10-27：Agent 配置引用修正

本地回归确认：把配置中的完整 `${DB_PASSWORD}`、`${DB_PASSWORD:}` 与 YAML 空标量当成秘密字面量，
会阻止不含凭据值的普通 Spring Boot 配置写入。旧 Step 4 的拟写入值未保留，不能据此反推旧两次拒绝的全部内容。

在 Agent 的 `.properties` / `.yml` / `.yaml` 源码视图与写入检查中，允许完整的单个配置引用，
引用名为有界的字母/数字/下划线/点/连字符，默认值只允许为空；YAML 额外允许引号空值与行尾注释。
不求值环境、不解析 Java 或 YAML AST、不允许任意拼接、非空秘密默认值或测试路径白名单。
`.properties` 的引号空串仍是实际字节，不当作 YAML 空值；源码字符串 `${...}` 也不当作运行时配置引用。
已知令牌、私钥、Authorization、连接串等规则独立生效，引用语法不能隐藏它们。

真实凭据行的替换、删除和改成引用仍由旧行保护拒绝；新增真实凭据同样拒绝。
M1–M3 的保守净化、明确凭据路径、逐文件前后像、最终捕获/重放与正式 Delivery 完整性均不变。
这是现有确定性配置规则的修正，非领域状态或模块边界变更。
