# ADR-0032　按目标模型投影完整对话批次

本决定更新 ADR-0030 的跨模型重放方式。此前一条助手消息的私有部件无法重放，就能使整段执行历史退回编号引用，即使提示仍有足够空间。

## 决定

SQLite 保管原始记录。读取未覆盖的记录时按所属 Run 比较冻结配置，用助手记录号和提供方调用 ID 关联真实 invocation。先在原记录上检查完整配对和未回应用户输入，再为候选请求投影批次。当前视图、压缩后的候选尾部和超限时的临时视图均按其实际前缀重新投影。检查点仍引用原始记录号。

新助手回复在原有私有 JSON 中附带实际工具定义和消息前缀的 SHA-256 链摘要。这样能识别检查点推进、裁剪、强度或账户变化。冻结配置相同、前缀吻合且所需推理齐全时使用原生有序部件。旧记录缺少摘要时使用公开部件或执行资料。无需数据库迁移。

公开结构化批次按原顺序重建文本和函数调用，舍弃附加属性、推理、签名及未知部件。受限字符、过长或冲突的调用 ID 以批次记录号和调用位置映射，回执使用相同 ID。现有 Spring AI ChatModel、传输层和估算器均收到这份投影视图。

无法结构化表达的批次生成一条普通历史资料消息，保留可见答复、参数、实际回执及查询入口。回执正文包含执行时已限长的输出及可用的超时、截断、缺口等字段。对没有可靠来源的旧记录，缺失事实保持未知。

## 原生协议边界

DeepSeek Chat Completions 无法插入外部生成的工具调用。启用思考且携带工具时还须回传此前助手轮次的推理。外部批次在关闭思考时也需转成资料。在默认或启用思考的模式下，缺少有效推理的助手文本同样作为资料。保留 Kimi 已有的思考模式工具约束。Gemini 当前工具轮次需要签名，当前轮次中来源不兼容的调用使用资料，已完成的历史轮次可以保留公开调用及配对结果。
