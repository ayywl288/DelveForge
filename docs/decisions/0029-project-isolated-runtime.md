# ADR-0029 项目独占开发环境与前台执行名额

本决定更新 [ADR-0028](0028-project-conversations-and-shared-environment.md) 的部署拓扑和准入范围。Project、Conversation、Run 的授权及四个工具的协议继续适用。

## 部署

宿主控制端按需为项目启动开发容器、公共下载代理、Go 网关和 Windows 回环入口。开发容器只绑定该项目的 Windows 工作副本和私有持久卷。容器的可写系统层保存项目安装的软件。HOME、Maven 本地仓库、Wrapper、npm 和 pnpm 缓存保存在私有卷。原仓库、Docker 管道、模型密钥和控制数据库仅供宿主控制端使用。

每代环境拥有内部桥接网络及出口网络，Docker 为每组分配两个独立的 /28 子网（10.240.0.0/12 中避免重叠的子段）。开发容器只接内部网，出口代理限制私网、宿主及内部目标，回环入口及代理禁用 IP 转发。网关与本项目开发容器共享网络命名空间，控制连接使用该代独立的双向 TLS 证书。查询在项目、对话及调用作用域内校验。预览仍绑定原监听服务。

默认每个开发容器最多使用 2 CPU、3072 MiB 内存、768 个进程，适用于本机中等规模的 Java 或前端构建。两个同时构建的项目最高可占用约 6 GiB 开发容器内存，Docker 引擎和辅助服务还需要余量。大型构建可调整 `delveforge.workbench.project-cpus`、`project-memory-mib` 和 `project-pids`（均使用相同配置前缀）；在下一次创建容器时生效。

## 准入与恢复

SQLite V7 以项目级唯一索引和全局限额共同约束准入。默认两个前台名额，使用 `delveforge.workbench.max-concurrent-runs` 配置。单个本机控制端在短事务中领取最早可运行的排队任务。排队和取消均持久化并保留原始用户消息。运行、正在停止、核对中及结果待核对的 Run 占用名额。后台服务数量和项目容器数量独立于前台名额。

控制端中断后逐个核对原容器 ID、启动代次、exec 和进程组。已经准入且有副作用的命令不自动重放。已结束但观测不完整的调用保留退出状态或输出缺口。项目维护用持久锁与调度互斥，新环境通过入口与出口检查后才切换登记。维护中断时依据原登记及切换日志核对已停组件。

## 全局工具镜像

项目没有 Docker 权限。推广必须由用户在宿主发起，先预览再确认。候选包须与基础镜像的发行版、架构、签名仓库归档和可执行内容相符。一次预览固定包及依赖的确切归档；确认时复核摘要，并仅将这些归档用于离线构建。新镜像经无挂载测试后，原子更新本机版本目录。原项目在显式升级前继续使用原镜像。升级会保留旧容器及其私有系统层，以便用户回退。

## 旧环境

原 V1–V6 的消息和调用保留原身份。旧环境尚有待核对命令时暂停新项目的准入。原共享容器和卷保留供恢复，按项目归属的持久目录可离线复制。旧系统软件无法可靠归属到具体项目，共享 Maven 本地仓库也可能包含私有安装物，二者均留在原环境。[迁移与回退步骤](../LOCAL_SETUP.md)
