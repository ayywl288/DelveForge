# 展示与面试交接

目标：用约 8 分钟讲清产品责任、关键工程实现和证据边界。冻结期不现场运行付费 Agent，
不依赖 Taskarium 注册/登录演示成功，不展示 key、数据库内容或完整模型输入。

## 展示顺序

1. **问题与用户（1 分钟）**：已有课程/教程项目的开发者，需要从个人需求与已有代码找到下一条可执行路线。
   展示 README 的需求→仓库→方向→计划→逐 Step 交付图。
2. **产品路径（1 分钟）**：说明用户确认画像、资产权限、方向选择和 Step 授权分别存在；
   新启动的无 key 实例可展示项目工作台与连通状态，不能演成真实模型对话。
   如选择读取已有实验页面，保持只读，不点生成/分析/启动。
3. **Agent（2 分钟）**：使用 [生命周期图](ARCHITECTURE_OVERVIEW.md#2-agent-与工具调用) 与
   [留存实施截图](../validation/evidence/step4-final-delivery-ui.jpg)，讲六个工具、精确编辑、
   Docker 隔离、Maven 检查副本、快照与 stale 证据、取消及 API 费用。
4. **正式交付（2 分钟）**：讲 R/D/B/C、持久化 INTENT、原生写入、CAS 与 SQLite 接受，
   用 [四步链路 JSON](../validation/evidence/step4-final-git-sqlite-proof.json) 对照 C1→C4；
   不把原始长 diff 或全部失败检查作为主展示内容。
5. **结果与取舍（2 分钟）**：对照下面两例，主动指出技术验证和实际使用的差别，
   以 MVP 冻结、保留失败证据与后续按价值授权收尾。

## 两个实验的对照

| 维度 | FinTrack | Taskarium |
| --- | --- | --- |
| 需求 | 登录用户隔离的交易 CSV 导出 | 多步个人任务、笔记、截止日期/进度、持久化与用户隔离 |
| 实现来源 | 真实 DeepSeek Agent；两次正式交付 | 真实 DeepSeek Agent；原四步正式交付 |
| 技术证据 | 展示版 12 项测试；Candidate/交付链 | 最终 34 项，原四步 9/19/28/34；完整累积 Git/SQLite 链 |
| 使用证据 | 真实登录、本人 CSV 与浏览器下载通过 | 启动通过，注册/登录 403，后续使用阻塞 |
| 人工介入 | Codex 修平台、反馈规划与独立验收，未代写目标业务 | Codex 修平台与验收工具，未代写目标业务、未改原四步定义 |

## 可用于简历准备的事实

- 个人开发本地项目探索与受控演化 MVP，Java 21 / Spring Boot 多模块、Vue 3 / TypeScript。
- 实现基于 Port 的模型/Workspace 集成、受控工具调用、Docker 隔离与源码快照绑定验证。
- 实现不可变 Candidate、Git CAS 与 SQLite 意图/接受协议，保留不确定失败现场并支持已知截面协调。
- 通过真实 FinTrack CSV 与 Taskarium 四步实验验证工程路径，区分自动化测试、正式交付和浏览器验收。

这些表述不包含未测吞吐、用户数、成功率、生产部署或商业收益。用“受控/有人监督的 Agent”，
避免“完全自动化无人值守”“任何项目都能演化”“所有 E2E 通过”等表述。

## 面试中的关键解释

**为什么不是直接让模型改仓库？** 原仓库只读，模型只改隔离源码，正式版本由独立确定性交付接受。

**如何处理 Git/SQLite 无法一起提交？** Git 前保存意图，重放确认目标树，CAS 发布；
SQLite 接受前重新证明实际状态。启动协调依据已知截面推进，不通过异常推断没写入。

**测试通过为什么仍失败？** Taskarium 测试手工附加 CSRF，而实际 HTML 表单没有该字段；
34 项通过不能替代用户浏览器旅程。该结果是测试覆盖边界的真实案例，不修改历史结果。

**为什么现在冻结？** 已有足够的产品流程、隔离、交付和失败处理证据。
继续为每个目标应用扩展平台不符合当前展示目的；保留明确限制，比无限开发更容易审阅和复现。
