# 工作台上下文与压缩

工作台按 Run 冻结的模型容量组装提示与检查点。[可重复执行的压缩回归](../backend/delveforge-infrastructure/src/test/java/com/ayywl/delveforge/infrastructure/workbench/ConversationCompactionTest.java)

## 模型每次收到哪些内容

SQLite 保存完整消息、工具协议、调用回执和已捕获输出。每段对话只有一份持久检查点，由 `summary`、`through_seq` 和 `context_version` 标识。发给模型的消息在请求前组装，包含系统指令、工具定义、当前检查点、选中的已覆盖用户原文及未覆盖的近期记录。

已覆盖的用户原文在整段对话内从新往旧选取。SQLite 每页读 32 条，使用带安全余量的模型输入估算器核算完整消息的边际用量。遇到下一条放不下时停止，已选消息以用户角色按时间顺序发送，保留最近一条省略原文的记录号。这样较老的要求不会越过一条未重放的修正重新出现。尾部消息只发送一次。尚未得到助手回应的连续用户输入全部保留。如果这部分连同系统指令和工具已经超限，Run 在发送前暂停。

每条独立用户消息、普通助手回复或完整工具批次构成一个切分单位。同一批次的助手消息、所有调用 ID 及对应的全部回执共同移动。保留的消息沿用原顺序、参数和思考字段。缺失、重复或孤立的回执会使 Run 暂停。切换思考模式后，若旧助手消息缺少当前适配器需要的推理字段，工作台按整批引用旧记录，继续保留兼容的近期批次。

## 预算与发布条件

设硬上限为 `usableInputTokens()`，软阈值为 `triggerTokens()`。工作台目标取 `targetTokens()` 与软阈值的 5/6 中较小者。这个上限让低阈值实验也有可测的余量。系统指令、工具描述、Schema 和实际保留的推理都计入决策输入。

| 项目 | 默认配置 | 长对话回归配置 |
| --- | ---: | ---: |
| 窗口 / 输出预留 | 1,000,000 / 65,536 | 9,200 / 1,200 |
| 可用输入 / 压缩阈值 | 934,464 / 841,018 | 8,000 / 6,400 |
| 压缩后目标 | 700,848 | 5,333 |
| 已覆盖用户原文上限 | 4,096 | 1,333 |
| 近期完整记录的初始预算上限 | 350,424 | 2,666 |

已覆盖原文最多占目标的 1/4，并封顶于 4,096 tokens，使长期任务的重放成本有固定上限。近期记录先分配至多目标的 1/2，实际固定提示与原文预留占用较多时再收紧。检查点和最新输入优先。原文及近期记录的具体条数随内容而变。[保留参数与切分规则](../backend/delveforge-application/src/main/java/com/ayywl/delveforge/application/workbench/ConversationRetention.java)

摘要请求单独计数，且不带工具。前缀放不下时，在完整批次边界上缩短前缀，因此决策尾部会变长。发送摘要前先测最小重建提示，拿到回复后再测包括新摘要、原文、尾部和工具在内的完整决策提示。通常只发布达到目标的检查点。原提示已经超过硬上限时，也可发布回到硬上限内、且至少减少「软阈值减目标」的结果。该结果可直接用于下一次决策。

## 检查点、失败与并发

新检查点由「上一检查点 + 新覆盖前缀」生成。三个栏目分别是用户要求、执行证据、待办与未知。摘要指令要求区分仍有效和已被取代的要求、助手推测与工具观察，保留精确的路径、标志、参数、验收键、已运行测试和输出缺口。

`[#N]` 中的 N 来自 `record.seq`。新摘要须至少引用一个新覆盖的真实记录号。沿用旧引用时，检查它是否来自给定的上一检查点或其边界，且在本对话中存在。助手可用 `df-workbench history N` 分页查到原文。原来保存的纯文本摘要仍可读取，新写入使用三个栏目。

发布时按预期 `context_version` 和递增的 `through_seq` 条件更新。版本竞争失败会从最新状态重建。本次压缩期间接收的输入留在冻结边界外。普通决策和工具准入继续检查新输入。

- 摘要截断、提供方报错、结构或来源无效、压缩量过小时，沿用仍符合硬上限的原提示。同一前台 Run 不为同一失败前缀反复请求摘要。发生足够的新增长或跨过硬上限时，新的前缀可以再试。暂缓记录位于内存，控制端重启后可以重新尝试。实际网络发送沿用适配器的重试与累计额度。
- 已超过硬上限时，临时视图保留已有检查点、已选用户原文、全部尚未进入检查点的用户原文，以及能够完整放入的近期批次。省略的执行记录给出可查编号。临时视图不更新覆盖位置或版本。必要内容仍放不下时，Run 暂停并保存原因。可以显式结束已暂停的 Run，再选择更大窗口的模型发起下一次任务。
