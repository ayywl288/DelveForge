# 领域模型

**Project** 拥有一个本机工作副本和项目专属的开发环境。导入完成后才接收 Conversation。原始目录只读；项目的各段 Conversation 共享副本，但消息、运行与历史查询按对话归属。文件本身可以由用户通过 Windows 编辑器修改。

**Conversation** 保存用户消息、公开时间线和模型偏好。收到新请求时先持久化；同一对话的请求 ID 用于确认和去重。执行中的纠正会阻止过时的工具提议或最终答复被采纳。

**Run** 在入队时绑定提供方、模型、协议、区域、思考强度、凭据版本、上下文窗口和输出预留。每个项目同时只有一个前台 Run，全局另有并行名额。额度按实际发出的模型请求计算，包括推理决策、摘要和重试。用量以提供方报告为准。

| 状态 | 允许的后续操作 |
| --- | --- |
| `QUEUED` | 符合项目和全局名额时启动，或由用户取消排队 |
| `RUNNING` | 接收同对话补充输入、执行已准入工具、完成、暂停或停止 |
| `STOPPING`、`RECONCILING`、`BLOCKED` | 保留前台占用，直到已准入的执行有明确的终止或待核对事实 |
| `PAUSED` | 显式继续同一 Run；没有未配对调用时可显式结束 |
| `COMPLETED`、`STOPPED`、`FAILED` | 保留历史，下一次任务可重新选择模型与思考强度 |

**工具调用** 保存稳定身份、提供方调用 ID、参数、容器及执行代次。控制端先准备、再准入，再执行。恢复时核对原执行；已产生的效果不能重放。每个提议最终对应一份回执。缺失输出或未知退出码须明确记录。

**历史与检查点** 保存原始消息顺序、用户要求、回执、证据引用及重建模型请求所需的私有部件。发布检查点要验证来源记录、连续覆盖范围和预期版本。模型与思考强度切换时，只有能够完整重放的批次进入新提示。无法容纳必需材料时暂停；历史记录仍可按原编号查询。[上下文与证据](WORKBENCH_CONTEXT.md)
